# 카페 키오스크 스마트 오더 시스템

## 1. 프로젝트 개요

고객이 카페 메뉴를 고르고 옵션을 설정한 뒤 결제까지 진행하는 Java 키오스크입니다. 주문 화면과 상품·장바구니·결제 로직을 분리하여 객체 간 협력과 객체지향의 네 가지 원리를 보여주는 것을 목표로 합니다. Swing 데스크톱 앱과 콘솔에서 같은 주문 로직을 사용합니다.

| 주요 기능 | 동작 |
|---|---|
| 메뉴 및 옵션 | 아메리카노, 카페라테, 레모네이드와 크루아상, 소금빵, 초코 머핀을 제공합니다. 음료에 따라 온도, 샷, 우유, 당도 옵션이 달라집니다. |
| 장바구니 | 상품과 옵션이 같으면 수량을 합치고, 옵션이 다르면 별도 항목으로 표시합니다. 수량 변경과 삭제를 지원합니다. |
| 주문 및 할인 | 매장 이용 또는 테이크아웃을 선택합니다. 시연용 학생증 번호 `DEMO2026001` 또는 `DEMO2026002`는 10%, 쿠폰 `CAFE1000`은 1,000원 할인입니다. 주문당 할인 한 종류를 적용합니다. |
| 모의 결제 및 영수증 | 카드와 현금 결제를 모의 처리합니다. 현금 부족 시 장바구니를 유지하며, 결제가 완료되면 주문번호와 영수증을 표시합니다. 주문번호는 실행 중에 관리합니다. |

## 5. 실행 방법

### IntelliJ IDEA

1. JDK 21을 설치한 뒤 저장소를 복제하거나 ZIP을 내려받고 압축을 풉니다.
2. IntelliJ의 **File → Open**에서 `README.md`와 `src`가 함께 있는 폴더를 엽니다.
3. **File → Project Structure → Project**에서 SDK를 **JDK 21**로 설정합니다.
4. `src`를 우클릭해 **Mark Directory as → Sources Root**를 선택합니다.
5. `src/kiosk/KioskGui.java`에서 `main` 옆의 실행 버튼을 누릅니다. 콘솔 버전은 `src/kiosk/KioskApp.java`의 `main`을 실행합니다.

### 터미널

저장소 루트에서 빌드합니다. Windows PowerShell에서는 다음 명령을 사용합니다.

```powershell
$javaFiles = (Get-ChildItem src/kiosk -Filter '*.java').FullName
javac -encoding UTF-8 -d out $javaFiles
```

macOS·Linux 셸에서는 다음 명령을 사용합니다.

```sh
javac -encoding UTF-8 -d out src/kiosk/*.java
```

빌드 후 실행할 버전의 명령을 입력합니다. Swing은 데스크톱 화면이 있는 환경에서 실행합니다.

```sh
java -cp out kiosk.KioskGui
java -cp out kiosk.KioskApp
```

## 6. OOP 적용 내용

| 원리 | 적용 클래스와 설계 이유 |
|---|---|
| 은닉성 | `Cart`의 항목 목록은 `private`으로 관리하고 읽기용 복사본을 반환합니다. `CartItem`은 생성 시 수량 범위를 검증해 올바른 상품 수량을 유지합니다. `OrderQuote`는 음수 주문 금액과 음수·주문 금액 초과 할인액을 거부합니다. |
| 상속성 | `Drink`와 `Bakery`는 추상 클래스 `MenuItem`을 상속해 상품명과 기본 가격 관리 기능을 재사용합니다. 각 클래스는 선택 가능 옵션을 제공합니다. |
| 다형성 | 화면은 `List<MenuItem>`의 상품에 같은 `options()` 메소드를 호출합니다. 실제 상품에 따라 음료 옵션이 표시되거나 베이커리의 빈 옵션 목록이 반환됩니다. |
| 추상성 | `DiscountPolicy`와 `PaymentMethod`는 할인과 결제의 공통 규약을 정의합니다. `OrderService`는 이 규약으로 할인액을 구하고 결제를 요청하며, 검증과 세부 계산은 각 구현 클래스가 맡습니다. |

## 9. 객체지향 설계 개선 내용

| 초기 설계 | 구현 및 변경 이유 |
|---|---|
| 음료 종류마다 하위 클래스를 만드는 구조 | 동작은 같고 옵션 구성이 다른 음료를 `Drink`로 구성했습니다. 상품과 추가금은 `MenuCatalog`에서 관리하고, 상품 유형의 공통 기능은 `MenuItem`으로 공유합니다. |
| 학생 여부를 직접 선택 | `StudentDiscount`가 등록된 시연용 번호를 검증하도록 변경했습니다. 학생 할인 적용 조건과 계산을 같은 객체에서 관리합니다. |
| 콘솔 한 종류로 시연 | Swing 진입점 `KioskGui`를 추가했습니다. 화면별 입력·출력은 각 진입점이 담당하고, 상품·장바구니·할인·결제·주문 객체는 두 화면에서 재사용합니다. |
| 화면마다 학생증·쿠폰 검증 처리 반복 | `DiscountService`가 할인 정책 생성과 유효성 검증을 담당하고 `Optional<DiscountPolicy>`를 반환합니다. 콘솔과 GUI는 번호 입력과 결과 안내를 맡습니다. |
| 화면마다 영수증 내용 작성 | `ReceiptFormatter`가 `Order`와 `OrderQuote`를 받아 영수증과 결제 금액 문자열을 생성합니다. 두 화면이 같은 출력 내용을 재사용합니다. |
| 할인 정책의 계산 결과를 바로 사용 | `OrderQuote` 생성 시 주문 금액이 0 이상인지, 할인액이 0부터 주문 금액 사이인지 검사합니다. 잘못된 할인 정책이 음수 결제 금액을 만들지 못하도록 보호합니다. |

이번 개선은 ChatGPT를 활용해 구현하고 검증했습니다. 학생 할인·현금 부족 후 쿠폰 카드 재결제 콘솔 시나리오와 공통 할인 검증, 잘못된 금액 거부, 현금 영수증 생성 테스트를 실행했습니다. 팀원의 직접 검토 및 변경 내역은 실제 수행 후 기록합니다.

GUI 영수증은 HTML 수평선을 사용해 표시 영역 너비에 맞게 구분선을 표시합니다. 이번 수평선 표시 변경은 전체 소스 컴파일로 확인했으며, 수정 후 실제 화면 표시는 재확인 예정입니다.
